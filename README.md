# stefan.kovarbasic — portfolio

Terminal / dark-mono portfolio site. **Astro + CSS Modules**, bilingual (EN + SR), zero client
frameworks — the only JavaScript shipped is ~1 KB of inline scroll-reveal and menu logic.

## Commands

```bash
npm run dev       # dev server at http://localhost:4321
npm run build     # static output in dist/
npm run preview   # serve the built output
npx astro check   # typecheck .astro + .ts
```

## Structure

```
worker/index.ts          ← POST /api/inquiry: Turnstile check, then email

  content/blog/          ← blog posts: <slug>/en.md + <slug>/sr.md

  lib/blog.ts            ← post loading, the both-languages check, RSS
  layouts/

  components/

```

### Editing content

Everything you'd want to change — jobs, skills, education, contact details, both translations —
lives in `src/i18n/content.ts`. Add a job by appending to `experience.jobs` in **both** `en` and
`sr`; the "current" badge is derived from the period text (`Current` / `trenutno`).

Projects work like skills: shared data (name, URL, stack) lives once in `WORK_PROJECTS` /
`PERSONAL_PROJECTS`, and each locale only supplies `kind` + `description` per project id — a
missing translation is a type error. The "at work" list puts its first project on a full row when
the count is odd, so the rest pair up.

To add a screenshot, save it as `src/assets/projects/<id>.png` (or `.jpg` / `.webp` / `.avif`),
e.g. `guestfriend.png`. It is picked up by file name and optimised to WebP at build time; until a
file exists the card shows a placeholder. Use a 16:10 capture (1440×900 works well) — the frame
crops to 16:10 from the top.

### Writing a blog post

Each post is a folder with one Markdown file per language — both are required, and the build
fails with a clear message if one is missing:

```
src/content/blog/my-post/en.md   → /blog/my-post/
src/content/blog/my-post/sr.md   → /sr/blog/my-post/
```

```yaml
---
title: 'My post'
description: 'One sentence for the post list and link previews.'
date: 2026-10-28
tags: ['astro', 'css']   # optional
draft: true              # optional — drafts show in `npm run dev` only
---
```

Copy `src/content/blog/example-post/` (a draft, never published) as a starting point. Images go
in the post's folder and are referenced relatively (`![Alt](./shot.png)`). Pushing to `main`
publishes. The **blog** nav link only appears once at least one post is published, so the live
site never links to an empty blog.

In Claude Code, `/blog-post` followed by the text does all of this. It translates the text into the
other language, writes both files, checks the build and pushes to `main` once you confirm. See
`.claude/skills/blog-post/SKILL.md`. Each language has an RSS feed at `/blog/rss.xml` and
`/sr/blog/rss.xml`.

Every component takes a `lang` prop and reads from `useContent(lang)`, so there is no runtime
language switching — each locale is a separately prerendered static page.

### Theming

All colours, fonts and spacing are CSS custom properties at the top of `src/styles/global.css`.
Changing `--accent` re-themes the whole site.

## Domain & deployment

Live domain: **https://kovar95.dev** (registered at Cloudflare Registrar, DNS on Cloudflare).

`site` in `astro.config.mjs` is set to it, and everything absolute derives from that single value:

- `<link rel="canonical">` and the JSON-LD `url`
- the `hreflang` alternates (Lighthouse rejects relative ones)
- `og:image` / `twitter:image` (social scrapers require absolute URLs)
- `sitemap-index.xml` and the `Sitemap:` line in `robots.txt`

`robots.txt` is generated by `src/pages/robots.txt.ts`, so it cannot drift out of sync. It also
serves `Disallow: /` on Cloudflare Pages **preview** deployments (any branch that is not
`main`/`master`), so the `*.pages.dev` previews never compete with the real domain in search.

### Cloudflare Workers setup

Deployed as a Worker with static assets — Cloudflare Pages is in maintenance mode as of 2026, so
new projects should start on Workers.

`wrangler.jsonc` holds the deploy config: it points at `./dist` and sets
`not_found_handling: "404-page"` so `src/pages/404.astro` is served for unknown routes instead of a
generic Cloudflare error. The only server code is `worker/index.ts`, and `run_worker_first`
limits it to `/api/*`, so page views are served straight from the edge without invoking it.

#### Inquiry form (services page)

`/website-development/` and `/sr/izrada-sajta/` post to `/api/inquiry`. The Worker validates the
fields, checks the Cloudflare Turnstile token server-side (success, action `inquiry`, hostname in
`TURNSTILE_HOSTNAMES`), then emails the inquiry through the `MAILER` send_email binding, with
Reply-To set to the visitor. The recipient must be a verified Email Routing destination, which is
free on every plan.

| Setting | Where | Value |
|---|---|---|
| Turnstile site key (public) | `TURNSTILE_SITE_KEY` in `src/components/InquiryForm.astro` | from the dashboard widget |
| `TURNSTILE_SECRET` | `npx wrangler secret put TURNSTILE_SECRET` | the widget's secret key |
| `INQUIRY_TO` | `npx wrangler secret put INQUIRY_TO` | the verified destination address (kept out of this public repo) |
| `TURNSTILE_HOSTNAMES` | `vars` in `wrangler.jsonc` | `kovar95.dev` |

The build fails until the site key is set, so a form that can never pass verification can't ship.

To run the form locally, create `.dev.vars` (gitignored) with Turnstile's test secret
`1x0000000000000000000000000000000AA`, `TURNSTILE_HOSTNAMES=example.com`,
`TURNSTILE_ALLOW_TEST_KEYS=true` and any `INQUIRY_TO`. Then build with the test site key and start
the Worker:

```bash
PUBLIC_TURNSTILE_SITE_KEY=1x00000000000000000000AA npm run build
npx wrangler dev
```

Locally, sent emails are written to `.wrangler/tmp/email/` instead of being delivered.
`npm run check` also typechecks the Worker; it regenerates `worker/worker-configuration.d.ts`
(gitignored) from `wrangler.jsonc` first.

Connect the GitHub repo in the dashboard (Workers & Pages → Create → Workers → connect a repo):

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Production branch | `main` |
| Environment variable | `NODE_VERSION` = `22` |

Then add `kovar95.dev` under the Worker's **Domains & Routes**. Cloudflare creates the DNS record
itself — do not add a CNAME by hand. `.dev` is on the HSTS preload list, so HTTPS is mandatory and
there is no http:// fallback to configure.

`SITE_URL` does **not** need to be set — the domain is the default in `astro.config.mjs`. Set it
only to build against a different origin.

To deploy by hand instead: `npm run deploy`.

### Regenerating the share image

`public/og.png` (1200×630) is a screenshot of the real hero, so it always matches the live design.
To refresh it after a design change, render the built page at 1200×630 with the header, footer,
non-hero sections, CTA row and scroll cue hidden.

## Lighthouse

Measured on the production build behind a server with gzip + cache headers (what Vercel, Netlify
and Cloudflare Pages all do):

| Page | Performance | Accessibility | Best Practices | SEO |
|------|------------|---------------|----------------|-----|
| `/`     | 100 | 100 | 100 | 100 |
| `/sr/`  |  99 | 100 | 100 | 100 |

Behind Cloudflare's CDN the real numbers should be at least this good — the measurement server was
a local one doing plain gzip, with none of Cloudflare's brotli or edge caching.

`/sr/` scores one point lower purely because Serbian body copy pulls Inter's `latin-ext` subset
(+85 KB) for `š ć č ž đ`; English does not need it.

Note that serving `dist/` with a plain `python3 -m http.server` reports a worse Performance score —
that server sends no compression and no `Cache-Control`, which a real host provides.

### Accessibility notes worth preserving

- `--text-faint` is the lowest-contrast text token and is tuned to stay **≥5:1 against every
  surface token**. If you darken it, small mono labels drop below WCAG AA (4.5:1).
- The logo link has no `aria-label`: its accessible name comes from the visible text, because an
  `aria-label` that does not contain the visible label violates WCAG 2.5.3 (Label in Name).
- The collapsed mobile menu is `inert` (plus `visibility: hidden`), so its links are not reachable
  by keyboard while hidden.
- The scroll-reveal script batches all layout reads before any class writes, so it never forces a
  reflow, and it reveals anything already in the viewport on `load`, `resize` and at page bottom —
  without that fallback a section can stay permanently invisible.

## Deploy

Static output — any host works.

- **Vercel / Netlify**: connect the repo, framework preset "Astro", build `npm run build`, output `dist`.
- **Cloudflare Workers** (current target): see the table above.
- **GitHub Pages**: push `dist/` or use the `withastro/action`. If you serve from a
  `user.github.io/repo` subpath, also set `base: '/repo'` in `astro.config.mjs`.
